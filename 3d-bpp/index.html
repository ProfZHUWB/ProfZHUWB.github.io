Introduction

One of main difficulties of multi-dimensional packing problems is the fragmentation of free space into several unusable small parts after a few items are packed. This study proposes a defragmentation technique to combine the fragmented space into a continuous usable space, which potentially allows the packing of additional items. We illustrate the effectiveness of this technique using the two- and three-dimensional Bin Packing Problem, where the aim is to load all given items (represented by rectangular boxes) into the minimum number of identical bins. Experimental results based on well-known 2D and 3D bin packing data sets show that our defragmentation technique alone is able to produce solutions approaching the quality of considerably more complex meta-heuristic approaches for the problem. In conjunction with a bin shuffling strategy for incremental improvement, our resultant algorithm outperforms all leading meta-heuristic approaches based on the commonly used benchmark data by a significant margin.

Data Sets

For the 2D Bin Packing Problem (2D-BPP), we considered two sets of standard benchmark instances. The first set was generated by Berkey and Wang (1987) and consists of 6 classes, data/2D/Class_01.2bp to Class_06.2bp; the second set was generated by Martello and Vigo (1998) and consists of 4 classes, data/2D/Class_07.2bp to data/2D/class_10.2bp. Each class of instances is further divided into 5 groups, where every group consists of 10 instances with same number of items; the number of items per instance in the five groups are 20; 40; 60; 80; and 100, respectively. All 500 instances and their corresponding best known solution values were downloaded from here.

For the 3D Bin Packing Problem (3D-BPP), we used the 320 instances generated by Martello et. al. (2000) for our experiments. This set of instances consists of 8 classes, and each class is further divided into 4 groups. Every group consists of 10 instances with same number of items; the number of items per instance in the 4 groups are 50; 100; 150; and 200, respectively. This set of instances are reproduced by the instance generator on a linux server using the script data/3D/gen.sh (you must have gcc installed)

We also created three types of 3D-BPP instances:

  • Type 1 new 3D-BPP instances: duplicates each item in the existing test set 65 times, resulting in problem instances with 65 times more items.
  • Type 2 new 3D-BPP instances: duplicates each item in the existing test set 65 times, and the bin size is doubled on each dimension (resulting in a bin that is 8 times larger).
  • Type 3 new 3D-BPP instances: are based on the requirements of the third party logistics company in question. They are divided into two classes, representing two common pallet-loading scenarios, where the height of a pallet is either half of a standard 20-foot container (allowing two pallets to be stacked), or it is the entire height. The unit of measurement is centimetres for better granularity. Each class is further divided into 5 groups, each consisting of 10 problem instances with 2000; 4000; 6000; 8000; and 10000 items, for a total of 100 instances. The dimensions of the items are based on actual data provided by the company. We varied the sizes of each item within a range of +/-10 cm for each dimension, resulting in heterogeneous instances; this increases the difficulty of the problems, and models the common scenario where third party logistics companies are required to pack and redistribute several similar but slightly different products.

Type 3 instances can be found in data/T3 directory, where the input format is as follows:


  2000 1      #Number of items to be loaded; and the LB
  120 80 104  #The L, W, H of bin
  0 32 36 36  #The id, l, w, h of first item
  1 54 35 36  #The id, l, w, h of second item
  ...

Binary Executable

Make sure the Java Development Kit 1.7.0 or later is installed


  java -jar solver.jar options

Up to 13 options can be specified and passed to the solver. If you specify less than 13 options, the default values are used for the remainaining options. The 13 options from left to right are:

  • problemType: 2D, 3D, T3 or S3, default 3D. Where S3 means solve a single 3D bin packing instance, input format is the same as type 3
  • timeLimit: default 300 (seconds)
  • boxNumScale: default 1, the number of boxes in the input file will be multipled by this factor
  • binSizeScale: default 1, the dimensions of bin in the input file will be multipled by this factor
  • seed: default 1, the seed for the random number generator
  • dataDir: default data/<problemType>, the directory where data files are stored; for S3, this is the input file
  • outDir: default result/<problemType>; if binSizeScale is not 1, "x<binSizeScale>" will be appended; if boxNumScale is not 1, "x<boxNumScale>" will be appended
  • tryPush: default true, meaning enable PUSH_OUT
  • tryReplace: default true, meaning enable Inflate-and-Replace
  • sortEP: default false, meaning not sort Extreme Pionts
  • tryEPBeforePush: default false. If set to true, when place an item in a bin, it will first try all extreme point without PUSH_OUT first; when all extreme point cannot accommodate the current item, then it will try each extreme point with PUSH_OUT. This option is useful only if TryPush is true
  • binShuffleIterLimit: default Long.MAX_VALUE, controls iterations of bin shuffle. The solver will stop after this number of bin shuffle is applied, even if time limit is not reached yet.
  • boxSorter: default "VH", specify the rule for sorting the items for the initial solution:
    • VH: decreasing volume decreasing height
    • HV: decreasing height decreasing volum
    • AH: decreasing area decreasing height
    • HA: decreasing height decreasing area
    • CVH: clustered decreasing volume decreasing height
    • CHV: clustered decreasing height decreasing volume

For example, invoke the following command on Windows 


  java -jar solver.jar 2D 10 1 1 1 data\2D result\2D
will solve all 500 2D-BPP instances, with 10s per instance and random seed 1. The solutions found will be sotred in result\2D directory. Whenever a better solution is found it will be saved in separate file in the result\2D directory. The files are named using following fileds separated by a space
  • class: 1 to 10 for 2D; 1 to 8 for 3D, type 1, type 2; 1 to 2 for type 3
  • itemCount: the number of items in the input
  • instNum: the instance numer within the group: 1 to 10 for 2D, 3D, Type 1, 2; 0 to 9 for Type 3
  • binNum: the number of bins in the solution
  • "seed": the literal "seed"
  • seed: the random seed
  • "V 1": the literal "V 1"

Another example, that solve 3D-BPP instances with time limit of 30s: 


  java -jar solver.jar 3D 30 1 1 1 data\3D result\3D-30s

In this example, we want to solve the Type 1 new 3D-BPP intances with time limit 60s: 


  java -jar solver.jar 3D 60 65 1 1 data\3D result\3Dx65-60s

In this example, we want to solve the Type 2 new 3D-BPP intances with time limit 60s: 


  java -jar solver.jar 3D 60 65 2 1 data\3D result\3Dx2x65-60s

In this example, we want to solve the Type 3 new 3D-BPP intances with time limit 60s: 


  java -jar solver.jar T3 60 1 1 1 data\T3 result\seed=1\T3-60s

Detailed Results

Our algorithms were implemented as sequential algorithms in Java. The experiments were conducted on a PC with an Intel Core i7 920 CPU clocked at 2.66 GHz with 12GB RAM running Windows 7 64-bit edition. The 64-bit Java Development Kit 1.7.0 from Oracle was used to implement the algorithm. You will find the following files in results.zip: 


  2D-0.6s/    Solution files found by BS-EPSD with time limit 0.6s for 2D BPP
  2D-10s/     Solution files found by BS-EPSD with time limit 10s for 2D BPP
  2D-init/    Initial soluitons found by BS-EPSD for 2D BPP
  3D-1s/      Solution files found by BS-EPSD with time limit 1s for 3D BPP
  3D-30s/     Solution files found by BS-EPSD with time limit 30s for 3D BPP
  3D-init/    Initial soluitons found by BS-EPSD for 3D BPP
  T1-60s/     Solution files found by BS-EPSD with time limit 60s for Type 1 new 3D BPP
  T1-init/    Initial soluitons found by BS-EPSD for Type 1 new 3D BPP
